# Task1 规则版 vs 规则+本地LLM 对比

## 1. 对比范围

- 对比时间：`2026-04-10`
- 对比对象：
  - 规则版：`task1 classify --skip-db-load`
  - 规则+本地 LLM 版：`task1 classify --skip-db-load --use-llm --llm-max-rows 20`
- 对比输入：同一批 `213` 条原始文本
- 本地 LLM 后端：`ollama`

## 2. 总体结果

- 原始候选数：`213 -> 213`
- 结构化事件数：`82 -> 86`
- 净增结构化事件：`+4`
- 被本地 LLM 实际参与增强的结构化事件：`15`
- 共有字段改写的既有事件：`11`
- `industry_type=其他`：`49 -> 48`（收紧后下降）

结论：
- 本地 LLM 已经不是“摆设”，它会真实影响最终结构化结果
- 但它当前更适合作为“边界样本和高价值样本的辅助增强器”，不适合作为主判官

## 3. 正向收益

新增进入结构化事件的样本（示例）：
- `科技赋能春耕生产`：`行业类 / 科技`
- `物联网产业创新发展方案发布`：`政策类 / 科技`
- `春日经济带动文旅消费`：`宏观类 / 消费`
- `创新药审批与授权交易增长`：`宏观类 / 其他`

已有事件被增强的主要方向：
- 事件名更短、更适合标准事件口径
- 部分事件主体从笼统分类调整为 `政策类 / 宏观类`
- 部分科技政策类文本从 `其他` 调整为 `科技`
- 部分情绪从 `中性` 调整为 `利好`

代表性改写示例：
- `十部门发文规范人工智能科技活动伦理治理` -> `人工智能伦理审查办法发布`
- `具身智能领域首份行业标准发布——推动技术成果产业` -> `具身智能行业标准发布`
- `关于优化完善无线电频率占用费标准的通知...` -> `无线电频率收费政策调整`

## 4. 风险与不足

当前本地 LLM 并非单向优化，仍有两类主要风险：

1. `industry_type=其他` 占比未下降
- 旧版对比（收紧前）：`49 -> 52`
- 新版对比（收紧后）：`49 -> 48`

这说明锚点收紧后，行业归类稳定性有改进，但仍需持续监控模糊行业样本。

2. 部分地缘/宏观文本会被改写成更温和的政策/宏观口径

示例（收紧前风险样本）：
- `王毅同欧盟外交与安全政策高级代表卡拉斯通电话`
  - 规则版：`地缘类`
  - LLM 版：`政策类`

收紧后复测：
- `中欧外交通话` 已稳定为 `地缘类 / 其他 / 中性`
- `轻工业增加值增长`、`轻工业经济运行稳健` 已稳定为 `消费` 行业，不再被打回 `其他`

这说明：在外交、地缘、宏观交叉文本中，规则锚点可以有效抑制 LLM 对强语义的弱化。

## 5. 当前最合理的定位

本地 LLM 当前应该固定在以下角色：

- 边界样本辅助判定
- 高价值来源样本摘要与命名增强
- `industry_type=其他`、`subject_default` 等模糊样本的辅助修正

不应承担：
- 主判定逻辑
- 强规则负例翻盘
- 热度/强度数值评分
- 收益标签计算

## 6. 触发策略是否合理

当前触发条件包括：
- `borderline_score`
- `high_value_source`
- `industry_other`
- `subject_default`
- `duplicate_cluster`

从本轮结果看，这套触发策略是合理的，因为：
- 没有让明显的强规则负例大面积翻盘
- 确实补进了少量高价值事件
- 事件命名质量有提升

但也暴露出需要继续收紧的点：
- 不能默认信任 LLM 的行业归类
- 地缘 / 宏观 / 政策交叉文本需要更强规则锚点

## 7. 下一步优化建议

1. 保持“规则优先 + LLM 辅助”，不要让本地 LLM 接管主判定
2. 对 `industry_type=其他` 的样本做专项人工复核
3. 对地缘类和外交类样本加更强规则锚点，避免被 LLM 弱化
4. 下一轮对比重点看：
   - 新增事件的人工准确率
   - `industry_type=其他` 占比变化
   - 高价值来源样本的命名质量
