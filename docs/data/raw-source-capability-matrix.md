# 原始来源能力矩阵

> 目标：把 `raw_documents` 的扩容、历史补采、正文回填这三件事讲清楚。  
> 本文只讨论 raw 层，不依赖事件分类结果。  
> 更新时间：`2026-04-23`

## 原则

raw 层的优先级按下面三条判断，不按事件分类回溯：

1. **source-driven**：这个来源有没有稳定 collector
2. **time-driven**：2025/2026 是否覆盖太薄
3. **coverage-driven**：有没有正文、正文质量够不够

也就是说：

- `collect` 负责把来源和正文做厚
- `events` 负责把文本变成结构化事件

不要把这两层倒过来。

## 2025/2026 的具体目标

### A. CNInfo 历史公告

- 不参与“来源平衡”
- 只做一件事：**继续补缺正文**

### B. 非 CNInfo 来源家族

目标不是和 CNInfo 对齐，而是先进入相近量级。

建议目标带：

- **基础目标**：每个来源家族 2025/2026 至少 `150` 条
- **稳态目标**：主要来源家族尽量进入 `150-300` 条区间
- **暂停扩容例外**：`AKShare/EastMoney 新闻聚合` 暂不继续放大，先让更弱来源追上

### C. 正文策略

- 有详情页/附件回填能力的：优先补正文
- 没有详情页回填能力的：先补数量，再决定是否开发正文增强
